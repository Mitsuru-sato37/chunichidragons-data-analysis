# 1本目の動画制作計画

更新日: 2026-10-21
題材: 中日の現有戦力から見る、今回のドラフト戦略

## 動画の問い

**現状の中日の戦力に対して、今回のドラフトはどんな戦略だったのか。**

指名選手の名前が判明した後、選手の特徴と中日の一軍・ファームの選手層を照合し、指名の方向性を説明する。球団が明言していない指名意図は事実として断定せず、公開情報と指名結果から読める分析として示す。

## 先に準備すること

ドラフト前に現有戦力の比較材料を整理し、指名後は名前・順位を入力すれば同じ観点で照合できるようにする。

### 現有戦力側

- 一軍のポジション別選手、年齢、左右、今季の起用実績
- 控え・複数ポジション対応選手と、主力欠場時に担える役割
- ファームの同ポジション選手と、今季の起用・成績（取得できる範囲）
- 投手は先発・救援、右左、役割と年齢層を分ける
- 退団・戦力外・引退など、次季の人数や役割に影響する確定情報

各項目は「確認済み事実」「集計値」「分析上の見立て」を区別する。登録ポジションと実際の起用位置も混同しない。

### 指名選手側（指名判明後に入力）

| 項目 | 記録する内容 |
| --- | --- |
| 指名順 | 順位、支配下・育成の別 |
| 選手 | 氏名、所属、年齢 |
| 守備・役割 | 主な守備位置、投手なら先発・救援適性など公表情報 |
| 左右 | 投打、投手なら投球左右 |
| 選手像 | 公表プロフィールや複数ソースで確認できた特徴 |
| 実績・評価 | 大会・リーグ成績、スカウトコメント等。出典と対象期間を記録 |
| 中日側との対応 | 一軍・控え・ファームの誰／どの役割と重なるか、何が不足しているか |
| 読み取れる方向 | 即戦力、将来の後継、層の厚み、特徴の補完など。根拠と確度を添える |

氏名から情報を集める際は同姓同名を所属・年齢で識別し、公式プロフィール、所属先、信頼できる報道などで照合する。情報が確認できない欄は推測で埋めず「未確認」とする。

## 分析の手順

1. ドラフト前の戦力を、ポジション・投打・役割・年齢層・一軍／ファームで整理する。
2. 各指名選手のプロフィールと根拠のある特徴を確認する。
3. 指名選手を現有選手層に重ね、競争、補完、後継、育成のどれに近いかを検討する。
4. 指名順位、複数指名、左右や役割の偏りから、指名全体の共通方針を探る。
5. 別の説明が成り立つ点や未確認情報も添え、ドラフト戦略の評価を結論づける。

「ポジションが同じ」だけでは補強意図を決めない。年齢、役割、起用実績、ファームの候補、指名順位と全体の指名構成を合わせて見る。選手の能力評価とチームの編成意図も別々に扱う。

## 動画の流れ（指名後に数値・選手名を反映）

| 順 | 内容 | 画面の役割 |
| --- | --- | --- |
| 1 | 導入：「現状の中日に対して、今回のドラフトはどんな戦略だったのか」 | 問いを提示 |
| 2 | ドラフト前のチーム状況 | ポジション・左右・役割ごとの選手層を俯瞰 |
| 3 | 指名選手一覧 | 順位、名前、守備位置／役割、投打を一覧化 |
| 4 | 指名選手の特徴 | 公表情報と実績に基づき、各選手のタイプを簡潔に紹介 |
| 5 | 現有戦力との重ね合わせ | 同ポジションの一軍・控え・ファームと対応関係を示す |
| 6 | 指名全体から見える方針 | 重複、左右、役割、年齢層、順位の傾向をまとめる |
| 7 | 結論と今後の確認点 | 読み取れる戦略、まだ判断できない点、今後見るポイントを示す |

指名人数や情報量に合わせて選手紹介の尺を調整する。根拠が弱いポジション不足を先に決めて選手を当てはめる構成にはしない。

## 素材化する画面

- ドラフト前のポジション／役割別選手層
- 指名一覧（順位、選手、位置、左右、所属）
- 指名選手ごとのプロフィールカード（出典・時点を管理）
- 一軍・控え・ファームと指名選手の対応図
- 指名全体の構成（野手／投手、左右、位置、役割、順位）
- 「事実」「分析」「未確認」を見分けられる結論画面

画面は一つの問いに一つの答えを対応させる。細かい数字を詰め込まず、動画内で結論に必要なものだけ表示する。

## 表現・確認ルール

- 球団が公表していない指名意図は、確定事実として語らない。
- 選手の特徴や評価は出典を確認し、記事の表現をそのまま球団の意図に置き換えない。
- 一軍成績、ファーム成績、アマチュア成績を混ぜず、対象期間と水準を明示する。
- 出場数の偏りだけで選手層の薄さを断定しない。
- 数字は独立資料との照合後に公開用として確定する。データ・画像・記事の利用条件も別途確認する。
- 取得元、URL、確認日、利用条件を制作台帳に記録する。
